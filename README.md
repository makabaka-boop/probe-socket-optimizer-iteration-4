# 探针分配 · 最小权完美二分匹配

芯片老化台换批前，把等量探针（行）分配到测试座（列）。部分探针/测试座组合禁配，
不同组合有校准代价。服务端以 **O(n³) 匈牙利算法** 精确求解最小权完美二分匹配，
页面支持编辑代价矩阵、查看方案、排除单个配对后重算替代最优。
同一次求解还会做**必然连线分析**：标出每条展示配对是否出现在所有同价最优方案中，
并给出该探针的可替换连线数（O(n²) 等势子图强连通分析，不枚举排列）。

**校准成本更新后**可把当前完整配对固定为“旧接线参考”并发起**迁移求解**：服务先最小化
新矩阵总成本，再在所有同成本完美匹配中最小化相对参考的变更行数（两级目标独立求解，
不用可能越过安全整数范围的放大系数），返回新配对、精确费用与变更行。

## 接口

`POST /api/solve`

请求：`{ "costs": number[][] }`

- n = costs.length，1 ≤ n ≤ 400，必须为 n×n 方阵
- 元素只能是 `null`（禁配）或 `0..1_000_000_000_000` 的整数
- 行=探针，列=测试座

成功 `200`：

```json
{
  "status": "ok",
  "n": 4,
  "assignment": [3, 0, 1, 2],
  "totalCost": 205,
  "pairFlags": [
    { "forced": true, "alternatives": 0 },
    { "forced": true, "alternatives": 0 },
    { "forced": true, "alternatives": 0 },
    { "forced": true, "alternatives": 0 }
  ]
}
```

`assignment[i]` 为第 i 行探针匹配的列（0 基），是一个 0..n−1 的排列，
覆盖全部行与列；`totalCost` 为精确整数总和，可用配对对原矩阵直接复算。
存在多个最优解时任选其一。

`pairFlags[i]` 与 `assignment` 逐行对齐，**只针对本次实际展示的这组配对**：

- `forced`（稳定布尔）：`true` = 该连线出现在**每一个**同价最优完美匹配中（必然连线）；
  `false` = 存在另一个最优方案把该探针改配（可替换）。
- `alternatives`：该探针在最优解集合里还能改配的**其他列数量**；必然时恒为 0，
  与 `forced` 互为充分必要（`forced === (alternatives === 0)`）。

标记与方案、总价在**同一次响应**中给出；分析不改变求解器给出的配对与价格，
求解器仍可返回任一最优解。`409`/`422` 失败响应不携带方案，也不携带任何标记。

失败：

- `422 { "error": "INVALID_INPUT" }`：缺行、错维度、越界、非整数、JSON 非法等
- `409 { "error": "NO_PERFECT_ASSIGNMENT" }`：禁配关系下不存在完美匹配（违反 Hall 条件）

两类失败响应都不携带方案，页面会清除旧方案。

### 迁移求解（带 `reference`）

请求在 `costs` 外再带一个 `reference` 字段：

```json
{
  "costs": [[5, 5], [5, 5]],
  "reference": [0, 1]
}
```

`reference` 是长度 n 的 **0 基列下标排列**，表示上一批已核准的完整配对
（`reference[i]` = 探针 i 原接的测试座）。校验规则：

- 必须是长度 n 的数组，每项为 0..n−1 的整数且列不重复；
  规模不符、越界、重复列、字段非法都在**求解前整批拒绝**（`422`），即使矩阵本身可解也不求解。
- **不校验参考边在新矩阵中是否仍允许**：参考配对即使已落在禁配格上，仍可用于计算变更行数
  （该行不可能保留旧列，必然计入 `changedRows`）。

求解分两级、**独立跑两次匈牙利，不用任何放大系数合并权重**
（代价上界 1e12 × 400 已接近 2^53，乘上大于 n 的系数可能越过安全整数范围）：

1. 对新矩阵求最小总代价 `totalCost*` 与终态势函数；互补松弛保证：完美匹配最优当且仅当
   它全部由紧边（松弛为 0 的允许边）组成。
2. 只在紧边子图内构造 0/1 权矩阵——与参考同列记 0、换列记 1、非紧/禁配记 Infinity，
   再求一次最小权完美匹配。所得配对仍是新矩阵的最优匹配（第一级目标不增加），
   且**变更行数**（配对列与参考不同的行数）在所有同成本最优匹配中最小。

成功 `200` 在普通响应字段外增加：

```json
{
  "status": "ok",
  "n": 2,
  "assignment": [0, 1],
  "totalCost": 10,
  "pairFlags": [
    { "forced": false, "alternatives": 1 },
    { "forced": false, "alternatives": 1 }
  ],
  "reference": [0, 1],
  "changedRows": [],
  "changedCount": 0
}
```

- `reference`：回显归一化后的参考排列，页面据此核对响应归属（迟到/串台响应回显不一致即拒绝）。
- `changedRows`：相对参考发生换列的**行下标（探针，0 基）升序列表**；
  参考边已禁配的行自然包含在内。`changedCount` 为其长度。
- `pairFlags` 针对**新展示配对**、基于新矩阵的同成本最优集合用终态势函数重新做 SCC 分析，
  **不沿用旧方案/参考的必然标记**；迁移模式也可能全部必然或全部可替换。
- `totalCost` 始终从原始整数矩阵直接复算，与第二级 0/1 权无关，为精确安全整数。

迁移请求失败时同样返回 `409`/`422`，且不携带 `assignment`、`reference`、`changedRows`
等任何方案或归属字段。完全不带 `reference` 的旧版请求响应结构一字不变（无迁移字段）。

## 算法说明

标准 Hungarian（Kuhn–Munkres）势函数增广：维护行势 `u`、列势 `v` 与当前匹配 `p`，
每轮把一个新行挂到虚拟列 0，沿等势交错树用松弛 `a[i][j]-u[i]-v[j]` 扩展，
取最小 delta 平移势函数直到到达自由列，再回溯翻转增广。共 n 轮，每轮 O(n²)，
总计 **O(n³)**，不枚举任何排列。

- 禁配边以 `Infinity` 存储（`Float64Array.fill(Infinity)`），不参与松弛；
  若最小 delta 为 Infinity，说明自由列在允许子图中不可达（Hall 条件被破坏），
  立即返回无完美匹配。
- 代价最大 1e12、n 最大 400，总代价上界 4e14，小于 2^53，全程整数精确；
  总和直接对输入整数矩阵求和复算，不依赖势函数中间值。

### 必然连线分析（等势子图 + 强连通分量，O(n²)）

求解结束后复用终态势函数 `u/v`（满足允许边 `a[i][j]-u[i]-v[j] >= 0`，配对边上恰为 0）：

1. **等势（紧边）子图**：所有松弛恰为 0 的允许边。一个完美匹配最优，当且仅当它全部由紧边组成。
   禁配边（Infinity/null）永不紧；零价与重复代价天然落在紧边上，无需特殊处理。
2. 构造有向**交错图**：配对边画 `列 j → 行 i`，非配对紧边画 `行 i → 列 j`。
3. 展示配对 `(i,j)` 能被某个同价最优方案替换，当且仅当图上存在经过它的有向环，
   即行节点 i 与列节点 j 属于同一个强连通分量（迭代式 Tarjan）。不在同一 SCC
   ⇒ 该边被每一个最优完美匹配共用 ⇒ `forced=true`。
4. `alternatives` = 与行 i 同 SCC 内、由 i 出发的非配对紧边数（环上 i 可直接改配的不同列）。

断开图（如两个互不相干的紧边块）之间不会出现可替换；SCC 天然把这种边界算对。
接口只暴露稳定布尔与可替换数量，不返回势函数、邻接表、SCC 编号等内部中间态。

### 迁移两级目标（两次匈牙利，O(n³)，不合并权重）

设新矩阵代价为 a，旧接线参考为 r：

1. 第一次匈牙利：对 a 求最小总代价与终态势函数 u/v。由互补松弛，一个完美匹配 M 最优
   当且仅当 ∀(i,j)∈M：a[i][j]−u[i]−v[j]=0（全为紧边）。
2. 构造 0/1 矩阵 b：紧边且 j=r[i]（保留旧线）取 0，紧边且 j≠r[i]（换列）取 1，
   非紧边与禁配边取 Infinity；第二次匈牙利求 b 的最小权完美匹配 M。
   - M 全由紧边组成 ⇒ 在 a 上仍是最小总代价（第一级目标严格不增加，绝不“为保线加钱”）；
   - 权和 = #{i : M(i)≠r[i]} 即变更行数，取最小值即“所有同成本最优匹配中最少改动”。
3. `totalCost` 丢弃第二次的 0/1 权和，直接对 a 按 M 求和复算（精确安全整数）；
   `changedRows` 直接逐行比较 M 与 r 得到（升序）；参考边禁配时该行必然在其中。
4. `pairFlags` 用同一组 u/v 与新配对 M 重跑等势 SCC 分析（`analyzeTightMatching`），
   是新矩阵最优集合对新配对的结论，不沿用参考或上一轮的标记。

两级目标全程只有原始整数（≤1e12）与第二级的 0/1 参与运算，规模最大 400：
总代价上界 4e14、第二级权和上界 400，均远小于 2^53；**没有形如 a·B+Δ 的放大合并**，
因此不存在 B 选择不当越过安全整数范围的风险。

## 页面交互约定

- 请求进行中：矩阵格、规模、预设、提交按钮全部禁用（锁定编辑与提交）。
- 请求结束后任何编辑（改格、改尺寸、预设）立即清除旧方案、错误与必然标记。
- 成功响应上屏前逐条校验（防代理/缓存/滚动升级中的旧服务返回脏数据）：
  响应 `n` 必须等于当前矩阵规模；`assignment` 必须是长度 n、列不重复、
  不越界、不命中禁配格的合法排列；`totalCost` 必须是非负安全整数且与
  按当前矩阵逐项复算的总价精确相等；`pairFlags` 字段一旦存在，必须是长度 n
  且每项 `{ forced: boolean, alternatives: 0..n-1 }` 并满足
  `forced ⇔ alternatives===0`。任何一项不符都按 `PROTOCOL_ERROR` 处理：
  清除旧方案与旧高亮、不允许继续排除，绝不展示无法复算的“方案”。
  完全缺少 `pairFlags` 的旧版合法响应仍展示分配与总价，仅不显示分析标记。
- 每个配对可点“排除此配对”：该格被置为禁配（✕），经同一 `/api/solve` 重算，
  展示替代最优方案**并对新展示配对重新分析**（不沿用排除前的标记）；
  若替代问题无解则显示 409 并清除旧方案与标记。
- 方案区对返回配对独立复算总代价并与服务端数值比对。
- 配对卡片与矩阵格按标记高亮：绿色实边=必然连线，琥珀虚边=可替换；
  下方图例解释含义并汇总必然/可替换条数，悬停可见说明。

### 旧接线参考与迁移模式

- 任一方案上有“固定当前配对为旧接线参考”：把**当前完整配对**整批固定为参考（再次固定即整批替换，另有“清除参考”）。
- 固定后可改成本格、设禁配格、点随机预设后发起“迁移求解（少改线）”：
  **改格/禁配/预设不清除参考**；只有**改变矩阵规模**（应用新的 n）才清除参考与旧方案。
- 参考面板逐对显示 `探针→座`；某条参考边在新矩阵已禁配时标红“已禁配”——
  该行迁移时必然变更，但参考仍合法、仍可用于计数。
- 迁移结果区标题改为“迁移方案（同成本最少改线）”，配对卡片与矩阵格用
  蓝色实边标**变更行**、暗绿边标**保留行**，变更卡片附“由座 X 改配”徽标，
  下方列出变更探针行号与总数；必然/可替换标记是针对新配对重新分析的结论。
- 迁移方案下点“排除此配对”：该格置禁配并**沿用同一参考**再跑迁移（不退回普通模式、不沿用旧标记）。
- 归属与失败处理：迁移响应上屏前除常规校验外，还必须回显与本次固定参考逐行一致的 `reference`，
  且 `changedRows`/`changedCount` 能按当前矩阵与参考**逐项复算**；回显不一致（迟到/串台）、
  变更数对不上、请求失败（409/422/网络错误）时**不展示任何可操作的新接线**。
  迟到响应另有请求序号防护整体丢弃。失败只清除方案与错误，**参考保留**，改后可直接重试迁移。
